# aiwrtos
使用AI协助定制基于原版 OpenWrt、面向 x86 软路由的定制固件项目

## 仓库范围

本仓库仅提供原创构建文档、配置说明和维护记录，帮助 AI 或使用者从各项目官方来源获取源码并自行编译。仓库不提供预编译固件、第三方源码包或代理内核二进制。

## 维护规则

### 1. 文档与版本命名

- 构建指南统一放入 `build-guide/`。
- 文档按构建日期命名：`aiwrtos-vanilla-x86_64_YYYYMMDD.md`，例如 `aiwrtos-vanilla-x86_64_20261123.md`。
- 固件版本号同样按构建日期命名。
- 每次新的构建应新建对应日期的文档，不覆盖历史构建记录；修正文档错误时应在提交信息中说明原因。

### 2. 来源与版本核对

- 每次构建前重新查询 OpenWrt 最新稳定版及各组件版本，不将历史版本表视为永久的“最新版本”。
- 只使用项目官网、官方 Git 仓库和官方 Release 作为下载来源。
- 在文档中记录版本号、提交哈希、下载链接及可用的 SHA-256 校验信息。
- Tailscale 默认采用 OpenWrt 当前稳定版锁定的 packages feed；其他组件需要指定版本时，应有明确的兼容性或安全修复依据。

### 3. 构建环境

- 新构建环境推荐 8 核 CPU、16 GiB 内存和 150 GiB 磁盘；最低 8 GiB 内存和 120 GiB 磁盘。
- 使用普通用户编译，不直接使用 root。
- 后续更新保留 `build_dir`、`staging_dir`、`dl` 和 `.config` 以支持增量编译，不将 `make dirclean` 作为常规步骤。

### 4. 配置变更

- 配置修改应记录原因和适用范围，避免无目的地全局替换依赖或工具链。
- Go 工具链按软件包的 `go.mod` 和编译日志选择，不机械套用历史版本。
- PassWall 专用依赖的替换范围以官方 README 为准，不替换 Linux 内核或网卡驱动。
- 自定义内核不直接配置官方 kmod 仓库。

### 5. 发布前验证

- 至少执行镜像 gzip 完整性检查、关键软件包 manifest 检查和 SHA-256 计算。
- 核对默认 APK 软件源及预置 Mihomo 的实际版本输出。
- 未经实机验证时，只能描述为“编译及产物检查通过”，不得宣称启动、网卡、代理或 Tailscale 功能已经验收。

### 6. 安全与隐私

- 不提交内部 IP、SSH 密码、Token、订阅链接、节点信息、私人证书或其他凭据。
- 示例统一使用明显的占位符，公开前复查文档和提交历史。

### 7. 许可证

- 本仓库原创内容采用 Apache-2.0 许可证。
- OpenWrt 及其他第三方组件遵循各自原始许可证，本仓库的许可证选择不改变其权利和义务。
- 如果以后改为分发第三方源码、二进制或预编译固件，必须先单独审查并补齐相应的许可证、NOTICE 和源码提供义务。

### 8. 提交信息

- 新增构建指南使用：`docs: add build guide YYYYMMDD`。
- 修订维护规则使用：`docs: update repository maintenance rules`。
- 提交信息应说明实际变更，不使用“更新文件”等无法辨认内容的描述。
